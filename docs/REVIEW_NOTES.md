# Documentation review notes

Maintainer-only review record for the documentation PR. This is not part of the reader guide and is not a new scientific result. The original documentation review described the deployed annual/calendar application. The later observation-layer integration adds a separately labelled repository-only section; its source review and verification are in [observation-detail](../reports/observation-detail/VERIFICATION.md).

No model, source dataset, scientific result, code, deployment or branch history was changed by this documentation review. Historical reports remain intact. Where a report describes an earlier release, the guide states its scope instead of silently rewriting its result.

## Reproduction limits and unresolved implementation issues

| Item | Evidence and consequence |
| --- | --- |
| FRP cache identity | [FRP_TEST.md](../reports/review/frp/FRP_TEST.md) and [source_snapshot.json](../reports/review/frp/source_snapshot.json) require original clean caches, raw hashes and saved aggregation partitions. A fresh raw download alone is insufficient for this exact-cache gate. Publishing the committed verified payload is different from rerunning the original analysis. |
| Archive product versions | [METHODS.md](../METHODS.md) records observed MODIS version-field values and VIIRS version 2. The [manifest](../reports/data_manifest.json) has source hashes but no single uniform collection-version field. The guide reports the recorded values and does not infer one product collection from a calendar year. |
| Raw official-test root | [kill_test.py](../reference/kill_test.py) loads matching files from its input root without an analysis-year filter. The reproduction guide now uses a dedicated official-test archive root rather than accidentally including all baseline archive years. |
| Derived map and control order | [rhythm_web.py](../pipeline/rhythm_web.py) consumes existing reviewed map/control/newly-active-cell outputs. The guide places it after those inputs instead of implying they are generated by the exporter. |
| Count-cache identity | [area_cells.py](../pipeline/area_cells.py) and [extend_2025.py](../pipeline/extend_2025.py) reuse counts by source/output modification times and source filename. They do not have the streaming route's full byte/code identity check; colliding filenames across roots or stale caches require care. The guide states this limitation without claiming a code fix. |
| Publish branch check | [publish.ps1](../scripts/publish.ps1) accepts a branch argument but does not verify that the checked-out source branch equals it. A deployment build and pushed branch could differ if it is misused. The guide directs release users to check the branch and revision explicitly. |
| Missing full fresh rebuild | The documentation review inspected commands and dependencies; it did not redownload all archives or regenerate every frozen scientific artifact. The PR must not present those actions as completed. |
| Missing requested root report | There is no root `RESULTS.md` in this revision. The guide instead cites [the locked Layer 1 table](../reports/review/layer1_table.md), [official rhythm results](../reports/official/RESULTS.md) and individual review reports. |
| Browser verification boundary | Static file hashes do not test visual behavior, GPU support, evidence interactions or phone layout. Record the actual browser checks separately, including any untested cases. |

## Corrections made during documentation review

The background links to NASA's VIIRS attributes, FIRMS interpretation notes and MODIS transition guidance were independently opened. They support the measurement, orbital-drift and continuity wording without requiring a guessed retirement date.

The FAQ and glossary now distinguish raw zero counts, rounded area estimates, null fields and dates labelled no observation. Null calibration bounds in the extension are not satellite outage declarations. The glossary also separates time-zone clock rules from coordinate-to-zone lookup, clarifies across-track/along-track dimensions, and states that statistical significance is not a causal conclusion.

The FAQ's year-specific errors use the precision printed in the cited review: Bangladesh 2022 bias +113.6% and correlation 0.180; US correlation 0.968 in 2020 and 0.744 in 2024. No source numbers were changed.

The commands and architecture were independently reviewed by another agent. A separate numerical audit decoded the US daily data and matched every worked example in the README and user guide to its source at displayed precision, including monthly-history percentiles and the separate seasonal-study metrics.

The published site was opened for the US 2024 selection and the full 2003-2025 range. Checked labels and behavior include both calendar scales, sidebar scope, weekly evidence, annual Earth, monthly history, custom-area selection, instrument comparison, seasonal comparison, seasonal context, anomaly list, Evidence & validation, Weekly Rhythm Index, FRP, negative control, exploratory map and Methods. No browser console errors were captured during that check. This was a documentation inspection, not a fresh deployment verification or physical-device test.
